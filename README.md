# 생존일기 Web Frontend

청년의 지출 관리, 맞춤 정책 탐색, 생활비 절약 정보 검색, 커뮤니티 활동을 한곳에서 돕는 웹 서비스입니다.

현재 저장소는 제공된 목업을 바탕으로 만든 **React UI 프로토타입**입니다. 화면 이동과 반응형 레이아웃만 구성되어 있으며, 로그인·데이터 저장·API 호출·게시글 작성 같은 실제 기능은 아직 연결하지 않았습니다.

## 기술 구성

- React 19
- TypeScript
- Vite
- Wouter 경량 라우터
- Lucide React 아이콘
- CSS 디자인 토큰
- 예정 연동: Spring Boot REST API
- 모바일 앱: Flutter

## 시작하기

```bash
npm install
npm run dev
```

환경 변수는 `.env.example`을 복사해 사용합니다.

```text
VITE_API_BASE_URL=http://localhost:8080/api
VITE_APP_ENV=local
```

SNS 로그인을 사용할 때 `.env.local`에 공개 클라이언트 값을 추가합니다. Client Secret은 웹에 넣지 않습니다.

```env
VITE_API_BASE_URL=http://localhost:8080
VITE_KAKAO_REST_API_KEY=카카오_REST_API_KEY
VITE_NAVER_CLIENT_ID=네이버_CLIENT_ID
```

OAuth 콘솔 콜백 주소:

- 카카오: `http://localhost:5173/auth/callback/kakao`
- 네이버: `http://localhost:5173/auth/callback/naver`

## 기능 명세

### 1. 절약 일기

#### 1-1. 오늘 사용 가능 금액

- 사용자가 하루 지출 상한선을 직접 설정합니다.
- 홈 화면에서 사용 금액, 남은 금액, 진행률을 보여줍니다.
- 한도에 가까워지면 앱 알림을 제공합니다.
- MVP에서는 `안전 / 주의 / 초과` 세 단계만 사용해 복잡한 예측 기능은 제외합니다.

#### 1-2. 지출 등록

- 웹에서 금액, 카테고리, 결제 수단, 날짜, 사용처, 메모를 직접 입력합니다.
- Flutter 앱은 Android `NotificationListenerService`로 결제 알림을 감지합니다.
- 알림 원문은 Flutter 앱에서 사용자가 확인·수정한 뒤 Spring Boot 서버에 저장합니다.
- 웹은 서버에 저장된 지출 내역을 조회합니다.
- 카드사별 문구를 모두 자동 해석하는 기능은 초기 MVP 범위에서 제외합니다.

#### 1-3. 카테고리별 통계

- 월별 총 지출과 카테고리 비율을 보여줍니다.
- 이번 달과 지난달의 일별 지출을 비교합니다.
- 초기 버전은 월 단위 비교만 제공하고 복잡한 소비 예측은 제외합니다.

### 2. 청년 정책 맞춤 추천

#### 2-1. 사용자 조건 필터

- 나이, 거주 지역, 취업 상태를 입력합니다.
- Spring Boot 서버가 공공데이터를 조회하고 단순 조건 일치 방식으로 결과를 반환합니다.
- 초기 버전은 점수 기반 AI 추천 대신 조건 필터 결과를 사용합니다.

#### 2-2. 정책 상세

- 정책명, 대상, 지역, 예상 지원금, 신청 마감일을 보여줍니다.
- 상세 화면에서 원문 정책 페이지로 이동할 수 있습니다.
- 사용자가 관심 정책을 저장할 수 있도록 확장합니다.

### 3. 절약 지도

지도 화면은 공통 검색, 카테고리, 거리순·가격순 정렬 UI를 사용합니다.

#### 3-1. 착한가격업소

- 현재 위치 또는 검색 지역 주변의 업소를 지도와 목록으로 보여줍니다.
- 업소명, 주소, 대표 품목, 가격, 조사일을 제공합니다.

#### 3-2. 지역별 품목 평균 가격

- 마트별 실시간 할인 비교 대신 공공데이터의 지역별 품목 평균 가격을 제공합니다.
- 품목명, 지역 평균가, 조사일을 보여줍니다.
- 여러 마트 경유 경로와 장바구니 최적화는 데이터 부족과 구현 복잡도로 MVP에서 제외합니다.

#### 3-3. 공공시설

- 전국공공시설개방정보표준데이터 API를 사용합니다.
- 시설 유형, 사진, 운영시간, 가격, 시설 규모를 보여줍니다.
- API에 사진이 없으면 공통 기본 이미지를 사용합니다.

#### 3-4. 공영주차장

- 전국주차장정보표준데이터 API를 사용합니다.
- 무료·유료·혼합 여부, 기본시간·기본요금, 추가시간·추가요금을 제공합니다.
- 1일권, 월 정기권, 결제 방법, 평일·토요일·공휴일 운영시간을 제공합니다.

#### 3-5. 주거지 실거래가

- 완료된 부동산 실거래 내역을 목록으로 보여줍니다.
- 거래 금액, 계약일, 면적, 층, 건축 연도와 위치를 제공합니다.
- 사용자가 입력한 관심 매물과 주변 실거래 평균을 단순 비교합니다.
- 미래 가격 예측은 제공하지 않습니다.

#### 3-6. 필터와 정렬

- 거리순, 가격순, 최신 조사일순을 제공합니다.
- 카테고리마다 사용할 수 없는 필터는 숨깁니다.

### 4. 커뮤니티

- `자유게시판`, `정보 공유`, `절약 인증`, `질문` 네 카테고리를 제공합니다.
- 초기 버전은 게시글 목록·상세·작성·수정·삭제와 댓글만 구현합니다.
- 좋아요, 신고, 이미지 첨부는 핵심 CRUD가 안정된 뒤 추가합니다.

## 프로젝트 구조

```text
src/
├─ app/                         # 라우트 등록만 담당
├─ features/
│  ├─ dashboard/               # 홈·오늘 예산
│  ├─ expense-entry/           # 지출 등록
│  ├─ expense-statistics/      # 지출 통계
│  ├─ policies/                # 정책 추천
│  ├─ savings-map/             # 절약 지도
│  └─ community/               # 커뮤니티
└─ shared/
   ├─ layout/                  # 전체 내비게이션과 상단 바
   └─ styles/
      ├─ tokens.css            # 색상·여백·크기·그림자 공통 변수
      └─ global.css            # 공통 요소 스타일
```

각 기능 폴더는 `pages`, `styles`, `mocks`를 자체 소유합니다. 기능 담당자는 자신의 폴더 안에서 화면과 기능을 함께 완성하는 것을 원칙으로 합니다.

## 충돌을 줄이는 협업 방식

1. 이슈 하나를 한 명이 맡습니다.
2. 브랜치는 `이름/feat/기능명` 형식으로 만듭니다. 예: `kwaneon/feat/policy-detail`
3. 담당 기능 폴더만 수정합니다.
4. 공통 색상·여백은 `src/shared/styles/tokens.css`의 변수만 사용합니다.
5. 공통 파일 변경이 필요하면 기능 작업과 분리된 커밋으로 만들고 팀에 먼저 공유합니다.
6. 큰 페이지를 여러 명이 동시에 수정하지 않습니다.
7. PR은 가능한 한 하나의 이슈만 해결하도록 작게 유지합니다.

## 백엔드·앱 연동 원칙

```text
Flutter 앱 ─┐
            ├─ Spring Boot REST API ─ 데이터베이스·공공데이터 API
React 웹 ───┘
```

- React와 Flutter가 데이터베이스에 직접 접근하지 않습니다.
- 공공데이터 API 키는 Spring Boot 서버에서만 관리합니다.
- 날짜는 API에서 ISO 8601 형식(`YYYY-MM-DD`)을 사용합니다.
- 금액은 문자열이 아닌 정수 원 단위로 주고받습니다.
- 프런트엔드는 기능 폴더 안에 API 모듈을 두고 다른 기능의 내부 모듈을 직접 참조하지 않습니다.

## 우선순위 기준

- `P0`: 로그인 이후 핵심 사용 흐름을 만들기 위해 가장 먼저 필요한 기능
- `P1`: 서비스의 주요 가치를 완성하는 기능
- `P2`: 핵심 기능이 안정된 뒤 추가할 확장 기능

세부 개발 항목과 완료 조건은 GitHub Issues에서 관리합니다.
